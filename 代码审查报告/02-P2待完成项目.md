## 二、治理与引用面（按实际调用链评估，2026-08-16 复审 + v9.19 实测核对）

### 2.1 实际调用链（grep 核对结果）

```text
vxapo-app (Tauri, src-tauri/src/lib.rs)
  └─ std::process::Command("vxapo-cli.exe")
       └─ vxapo-cli (Rust bin，Cargo.toml 依赖 vxapo-driver)
            └─ vxapo-driver (Rust lib)
                 ├─ install/device/info::enumerate_devices
                 ├─ install/device/info::detect_mode_for_guid
                 ├─ install/device/slots::{InstallMode, SlotValue, ChildApoKind,
                 │     child_apo_key_exists, read_child_apo_guid}
                 ├─ install/selector/operation::{InstallConfig,
                 │     install_endpoint, uninstall_endpoint}
                 ├─ install/audiodg::stop_audio_service
                 ├─ object/dll_exports::register_apo_with_path
                 ├─ object/vx_reg_props::{CLSID_VXAPO_PRE_MIX, CLSID_VXAPO_POST_MIX}
                 ├─ sys/com/prelude::guid_to_string
                 └─ sys/registry::{RegKey::open, RegKey::create}
```

- APP 不链接 driver，不直接引用任何 `vxapo_driver::*`；安装/卸载经 CLI 进程边界。
- CLI 是 driver 唯一 Rust 库消费方；driver 的 `pub mod` 面对 APP 不可见，仅对 CLI 可见。
- `select.rs` 的 `select_device`/`run_install_flow`/`run_uninstall_flow`/
  `print_device_list`/`prompt_user` 在 driver 与 CLI 中均无调用点（CLI 有自有交互实现）——v9.19 已删除该文件。

### 2.2 治理项评估

| # | 项 | 优先级 | 实际调用链结论 | 动作 |
|---|----|--------|----------------|------|
| 1 | `api` 薄层 + DTO | 🟢 观察项 | APP 经 CLI 进程边界 + config.toml 已获得稳定面；当前不存在第二个 Rust 库消费方 | 不立项 |
| 2 | 内部模块可见性收敛 | 🟢 观察项 | 唯一消费方 CLI 与 driver 同仓库受信任；收敛收益为零 | 不实施，随 #1 触发 |
| 3 | CLI↔driver 稳定接口清单 | 🟡 | 实测 CLI 只触碰上表列出的 13 个路径；其中写路径仅 `install_endpoint`/`uninstall_endpoint`/`register_apo_with_path` | 已把清单固化到本表；内部重构保持这些签名兼容 |
| 4 | select.rs 交互函数迁出 | ✅ v9.19 | grep 全仓无调用点（CLI 自有交互实现） | 已删除 `install/selector/select.rs` 与 `pub mod select` |
