# VxAPO Driver 安装与排障

## 1. 安装架构

### 1.1 设备与槽位

Windows 音频端点通过 FxProperties 下的 5 个槽位挂载 APO：

```text
LFX / GFX / SFX / MFX / EFX
```

VxAPO 支持三种安装模式：

| 模式 | PreMix 槽位 | PostMix 槽位 |
|------|-------------|--------------|
| `LfxGfx` | LFX | GFX |
| `SfxMfx` | SFX | MFX |
| `SfxEfx` | SFX | EFX |

### 1.2 安装流程

`install::selector::operation::install_endpoint` 负责完整安装：

1. 检查 `DisableProtectedAudioDG`。
2. 读取设备槽位与格式。
3. 写入 VxAPO CLSID 到对应槽位。
4. 备份原 APO 到 `HKLM\SOFTWARE\VxAPO\Child APOs\{GUID}`（如启用子 APO）。
5. 写入 `AudioEngine\AudioProcessingObjects\{CLSID}` 注册属性。
6. 安装后通过 `CoCreateInstance` 自检。
7. 重启/刷新音频服务。

### 1.3 卸载流程

`uninstall_endpoint` 只清除能确定属于 VxAPO 的部分：

- 删除 VxAPO CLSID 槽位。
- 删除 `Child APOs` 信息区。
- 尽量恢复原 APO。
- 不触碰其他第三方 APO。

## 2. 设备查询

`install::device::info::enumerate_devices` 是唯一的设备枚举入口，返回：

- 端点 GUID / 名称 / 状态。
- 安装模式。
- 5 槽位占用。
- 格式信息。
- 已安装版本。

## 3. 快照与回滚

CLI 通过 `snapshot` 子命令保存注册表基线：

- 安装前建立基线。
- 安装后可 `snapshot diff` 查看变更。
- 卸载后与最初基线对比。
- 支持 `snapshot restore` 恢复注册表状态。

快照只覆盖注册表，不包含 config.toml 文件。

## 4. audiodg 不加载的根因与修复

### 4.1 现象

VxAPO 已写入端点槽位，但 `audiodg` 不加载 `vxapo_driver.dll`。

### 4.2 根因

Windows 音频引擎读取槽位 CLSID 后，会继续查询：

```text
HKCR\AudioEngine\AudioProcessingObjects\{CLSID}
```

如果该键缺失，引擎会静默跳过该 APO。早期实现只写了 `HKCR\CLSID\{...}`，遗漏了 `AudioEngine` 注册键。

### 4.3 修复

`register_com_class` 现在会补写：

```text
HKCR\AudioEngine\AudioProcessingObjects\{CLSID}
    FriendlyName
    Copyright
    MajorVersion
    MinorVersion
    Flags = 0xd
    MinInputConnections
    MaxInputConnections
    MinOutputConnections
    MaxOutputConnections
    MaxInstances
    NumAPOInterfaces = 1
    APOInterface0 = {FD7F2B29-24D0-4B5C-B177-592C39F9CA10}
```

`unregister_com_class` 会同步删除该键。

## 5. 常见排查项

| 检查项 | 说明 |
|--------|------|
| 槽位值是否为 VxAPO CLSID | 确认安装是否生效 |
| `AudioEngine\AudioProcessingObjects` 键是否存在 | 缺失会导致静默拒载 |
| `DisableProtectedAudioDG` 是否为 1 | 保护模式下可能无法加载 |
| `ProcessingModes` 是否包含所需模式 | 缺失会导致引擎不调用 |
| 子 APO 路径是否存在 | 影响 child 委托 |
| 权限是否足够 | 安装/卸载需要管理员权限 |
