# VxAPO Driver 安装与排障

## 1. 安装架构

### 1.1 设备与槽位

Windows 音频端点通过 FxProperties 下的 5 个槽位挂载 APO：

```text
LFX / GFX / SFX / MFX / EFX
```

VxAPO 支持三种安装模式：

| 模式 | PreMix 槽位 | PostMix 槽位 |
|------|-------------|--------------|
| `LfxGfx` | LFX | GFX |
| `SfxMfx` | SFX | MFX |
| `SfxEfx` | SFX | EFX |

### 1.2 安装流程

`install::selector::operation::install_endpoint` 负责完整安装：

1. 检查 `DisableProtectedAudioDG`。
2. 读取设备槽位与格式。
3. 写入 VxAPO CLSID 到对应槽位。
4. 备份原 APO 到 `HKLM\SOFTWARE\VxAPO\Child APOs\{GUID}`（如启用子 APO）。
5. 写入 `AudioEngine\AudioProcessingObjects\{CLSID}` 注册属性。
6. 安装后通过 `CoCreateInstance` 自检。
7. 重启/刷新音频服务。

### 1.3 卸载流程

`uninstall_endpoint` 只清除能确定属于 VxAPO 的部分：

- 删除 VxAPO CLSID 槽位。
- 删除 `Child APOs` 信息区。
- 尽量恢复原 APO。
- 不触碰其他第三方 APO。

## 2. 设备查询

`install::device::info::enumerate_devices` 是唯一的设备枚举入口，返回：

- 端点 GUID / 名称 / 状态。
- 安装模式。
- 5 槽位占用。
- 格式信息。
- 已安装版本。

## 3. 快照与回滚

CLI 通过 `snapshot` 子命令保存注册表基线：

- 安装前建立基线。
- 安装后可 `snapshot diff` 查看变更。
- 卸载后与最初基线对比。
- 支持 `snapshot restore` 恢复注册表状态。

快照只覆盖注册表，不包含 config.toml 文件。

## 4. audiodg 不加载的根因与修复

### 4.1 现象

VxAPO 已写入端点槽位，但 `audiodg` 不加载 `vxapo_driver.dll`。

### 4.2 根因

Windows 音频引擎读取槽位 CLSID 后，会继续查询：

```text
HKCR\AudioEngine\AudioProcessingObjects\{CLSID}
```

如果该键缺失，引擎会静默跳过该 APO。早期实现只写了 `HKCR\CLSID\{...}`，遗漏了 `AudioEngine` 注册键。

### 4.3 修复

`register_com_class` 现在会补写：

```text
HKCR\AudioEngine\AudioProcessingObjects\{CLSID}
    FriendlyName
    Copyright
    MajorVersion
    MinorVersion
    Flags = 0xd
    MinInputConnections
    MaxInputConnections
    MinOutputConnections
    MaxOutputConnections
    MaxInstances
    NumAPOInterfaces = 1
    APOInterface0 = {FD7F2B29-24D0-4B5C-B177-592C39F9CA10}
```

`unregister_com_class` 会同步删除该键。

## 5. 常见排查项

| 检查项 | 说明 |
|--------|------|
| 槽位值是否为 VxAPO CLSID | 确认安装是否生效 |
| `AudioEngine\AudioProcessingObjects` 键是否存在 | 缺失会导致静默拒载 |
| `DisableProtectedAudioDG` 是否为 1 | 保护模式下可能无法加载 |
| `ProcessingModes` 是否包含所需模式 | 缺失会导致引擎不调用 |
| 子 APO 路径是否存在 | 影响 child 委托 |
| 权限是否足够 | 安装/卸载需要管理员权限 |

## 6. 旧 GUID 残留：检测、迁移与清理（v9.10 起）

### 6.1 成因

Windows 重新枚举音频端点后，端点 GUID 可能变化（换 USB 口、驱动重装、蓝牙重新配对等）。
旧端点的槽位键已经消失，但 VxAPO 自己的记录仍在：

- `HKLM\SOFTWARE\VxAPO\Child APOs\{旧GUID}` 子 APO 备份与安装信息区。
- `C:\ProgramData\VxAPO\{旧GUID}\config.toml` 配置目录。
- `C:\ProgramData\VxAPO\snapshots\{旧GUID}.json` 注册表基线快照。

结果：新 GUID 显示"未安装"，旧配置与快照却还占着磁盘，用户需要手工搬运。

### 6.2 稳定身份与匹配

`install/device/stale.rs` 以**设备实例 ID**（`DeviceInstanceId`，如 `BTHENUM\...`）作为稳定身份，
把旧 GUID 记录匹配到当前活跃端点：

| `target_state` | 含义 |
|----------------|------|
| `matched_healthy` | 匹配到活跃端点，且该端点已健康安装 |
| `matched_partial` | 匹配到活跃端点，但安装不完整（需要迁移修复） |
| `unmatched` | 没有对应活跃端点（只能清理） |

### 6.3 API 与命令

```rust
pub fn list_stale_installs() -> Result<Vec<StaleInstall>>;   // 扫描 + 匹配（只读）
pub fn migrate_install(from, to, config_from, snapshot_from) -> Result<MigrationReport>;
pub fn cleanup_orphan(guid: &str) -> Result<()>;             // 清理无法匹配的记录
pub fn fix_config_acl(guid: &str) -> Result<()>;             // 迁移后修用户 ACL
```

- `StaleInstall` 字段：`guid` / `device_instance_id` / `display_name` / `config_path`、
  `config_mtime_ms` / `snapshot_path`、`snapshot_mtime_ms` / `premix_slot` / `postmix_slot` /
  `inferred_mode` / `has_child_backup` / `has_sysfx_backup` / `target_guid` / `target_name` / `target_state`。
- `MigrationReport` 字段：`success` / `target_guid` / `config_from` / `snapshot_from` /
  `config_migrated` / `snapshot_migrated` / `install_repaired` / `removed_guids` / `warnings`。
- CLI 入口：`vxapo-cli stale list|migrate|cleanup|fix-acl`（见 CLI 引用规范 §5.6）；
  App 通过 `StaleInstallBanner` 在选中设备页内提示并一键迁移/清理。

### 6.4 迁移流程

```text
stale migrate --from <旧GUID> --to <新GUID>
  -> require_admin
  -> 停音频服务 + taskkill audiodg（释放槽位/信息区占用）
  -> migrate_install：
       config_from / snapshot_from 缺省时，在"同设备实例的旧记录"与"目标现有文件"之间
       按「最新 config、最早 snapshot」选择来源
       迁移 config.toml 与 snapshot -> 修复新 GUID 安装状态 -> 删除旧 GUID 记录
       迁移前的目标文件备份到 C:\ProgramData\VxAPO\_migration_backup\{guid}\
  -> 输出 MigrationReport（JSON）
  -> 失败时恢复 audiosrv
```

迁移由提权 CLI 完成，`config.toml` 可能继承管理员 ACL；App 首次写入遇到"拒绝访问"时
会调用 `stale fix-acl` 给交互用户授予 Modify（`icacls` SID `*S-1-5-4`）后重试写入。

### 6.5 卸载兜底

若端点键已被 Windows 移除（`find_endpoint_path` 失败），但该 GUID 仍在残留列表中，
`vxapo-cli uninstall` 会直接转 `stale cleanup`，避免留下 Child APOs 键与配置目录。
