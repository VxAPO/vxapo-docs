# VxAPO Driver 架构与模块规范

## 1. 模块总览

`vxapo-driver` 是一个 Windows APO DLL，向 `audiodg.exe` 提供实时音频 DSP 能力。代码按以下模块组织：

```text
src/
├── lib.rs          # crate 根，声明模块
├── sys/            # FFI 层：COM、注册表、音频基础定义
├── pipeline/       # 音频处理管道：上下文、缓冲、格式、链、处理、DSP
├── install/        # 设备 APO 安装/卸载、设备查询
├── config/         # 配置文件解析（TOML 模型）
├── object/         # COM 胶水层：ApoObject、类工厂、DLL 导出
├── telemetry/      # 无锁日志与 panic hook
└── utils/          # 通用工具：对齐、GUID、错误类型
```

依赖方向保持单向：

```text
sys  ← pipeline ← config
  ↑       ↑         ↑
  └───────┴─────── object（唯一允许依赖所有模块的胶水层）
```

## 2. 模块职责与依赖

### 2.1 `sys/`

只依赖 `windows` / `windows-core`，不感知业务。

- `sys/com/prelude.rs`：COM 基础类型、HRESULT 常量、`guid_to_string` 安全封装。
- `sys/com/apo_interfaces.rs`：APO 接口与 IID 常量。
- `sys/com/apo_types.rs`：APO 相关 POD 类型。
- `sys/registry.rs`：`RegKey` RAII 封装，提供最小权限读写。
- `sys/audio_defs.rs`：声道掩码、标准布局、通道名映射。

### 2.2 `pipeline/`

只处理音频数据，不感知安装、配置和 COM 对象。

- `context.rs`：`PipelineContext`，保存采样率、通道名等运行参数。
- `buffer.rs`：音频缓冲与预分配。
- `format.rs`：格式提取与转换。
- `interleave.rs`：去交织/交织。
- `chain.rs`：`Chain` 持有 `Vec<Box<dyn Filter>>` 与总延迟。
- `process.rs`：正常处理与过渡处理入口。
- `realtime/`：`RealtimeContext` 编译期标记、无锁环形缓冲。
- `dsp/`：`Filter` trait、工厂、具体滤波器（biquad/FIR/PEQ/增益/响度/混响等）。

`pipeline` 不允许依赖 `install`、`config`、`object`。

### 2.3 `install/`

负责设备 APO 的安装、卸载与设备信息查询。

- `device/endpoint.rs`：端点状态/名称。
- `device/format.rs`：WAVEFORMATEX 解析。
- `device/slots.rs`：5 个 APO 槽位读取、安装模式、子 APO 路径。
- `device/info.rs`：`enumerate_devices` 唯一设备枚举入口。
- `device/sysfx.rs`：CAPX 默认效果模板接管/恢复。
- `selector/operation.rs`：`install_endpoint` / `uninstall_endpoint`，事务回滚。
- `audiodg.rs`：`DisableProtectedAudioDG` 检查与音频服务控制。

`install` 不允许依赖 `pipeline`、`config`。

### 2.4 `config/`

负责把 `config.toml` 解析为 DSP 链模型，但不直接操作 `Chain`。

- `model.rs`：`FileModel`，TOML 反序列化目标。
- `parser.rs`：`FileModel -> ChainModel -> Filter 链`，并产出 spec 指纹。
- `error.rs`：配置错误类型。
- `watcher.rs`：监控配置目录变化，触发热重载。

`config` 不允许依赖 `install`、`object`、`pipeline/process`、`pipeline/chain`、`pipeline/context`。

### 2.5 `object/`

COM 胶水层，被 Windows 音频引擎直接调用。

- `apo.rs`：`ApoObject`，实现 APO 接口。
- `apo/*.rs`：初始化、协商、处理、子 APO、状态等子模块。
- `factory.rs`：`IClassFactory`。
- `ref_count.rs`：引用计数。
- `vx_reg_props.rs`：VxAPO CLSID 与注册属性。
- `dll_exports.rs`：`DllGetClassObject`、注册/注销。

`object` 是唯一允许依赖所有模块的层。

### 2.6 `telemetry/` 与 `utils/`

- `telemetry/logger.rs`：无锁环形日志，RT 路径零堆分配。
- `telemetry/panic.rs`：panic hook。
- `utils/align.rs`：SIMD 对齐。
- `utils/guid.rs`：GUID 反向解析。
- `utils/vx_error.rs`：统一错误类型与 HRESULT 映射。

## 3. 依赖规则

| 模块 | 可依赖 | 禁止依赖 |
|------|--------|----------|
| `sys/` | windows-rs / windows-core | 其他所有 |
| `pipeline/` | `sys/`、`utils/` | `install/`、`config/`、`object/` |
| `install/` | `sys/`、`utils/`、`object/vx_reg_props.rs` | `pipeline/`、`config/` |
| `config/` | `sys/`、`utils/`、`pipeline/dsp/{filter,model,factory}` | `install/`、`object/`、`pipeline/{process,chain,context}`、具体 DSP 实现 |
| `object/` | 所有模块 | 无 |
| `telemetry/` | `pipeline/realtime/ring` | `install/`、`config/`、`object/` |
| `utils/` | `windows-core` | 其他所有 |

第三方依赖：

- `rustfft`：FIR/PEQ 分块 FFT。
- `thiserror`：错误枚举派生。
- `once_cell`：`install/device/sysfx` 惰性初始化。
- `serde` / `toml`：`config` TOML 反序列化。
- `windows` / `windows-core` / `windows-implement` / `windows-interface`：COM 与系统 API。

## 4. 数据流

### 4.1 安装流程

```text
CLI/App
  -> install::device::info::enumerate_devices
  -> install::selector::operation::install_endpoint
       -> audiodg 检查
       -> 注册表槽位写入
       -> child APO 备份/恢复
       -> 安装后验证
```

### 4.2 配置加载与热重载

```text
LockForProcess
  -> object/apo.rs
  -> pipeline/format.rs 提取格式
  -> config/parser.rs 解析 config.toml
       -> FileModel -> ChainModel -> factory::create_from_model
  -> pipeline/chain.rs 构造 Filter 链
  -> 预分配临时缓冲
  -> 启动 watcher

watcher 检测 config.toml 变化
  -> 锁外解析新配置
  -> 与当前 spec 指纹比较
  -> 不同则构建新链并进入双链过渡
```

### 4.3 实时处理

```text
Windows 音频引擎
  -> object/apo.rs::APOProcess
  -> 检查状态与锁
  -> process_audio（正常模式）或双链过渡
  -> 去交织 -> Filter 链处理 -> 交织
  -> 错误策略
```

## 5. 线程安全模型

- `self.mutex`：保护 `ApoObjectInner`（链、过渡、临时缓冲等）。
- `self.ap_state`：保护格式/通道/锁定状态。
- `StateCell`：`AtomicU8` + CAS 实现无锁状态机。
- 延迟值使用 `AtomicU32`，RT 路径无锁读取。
- 两把锁不交叉持有。
- `hot_reload` 在锁外解析配置，锁内仅替换链指针。

## 6. 关键设计决策

- `Chain` 不拥有缓冲区；缓冲区由 `ApoObjectInner` 预分配。
- 双链过渡在 `object` 层管理，`SmoothingProvider` 只提供混合因子。
- `DspContext` 由调用方构造，`config` 不直接操作 `Chain`。
- 生产构建必须 `panic = "abort"`、`codegen-units = 1`，RT 路径禁止 unwind。
- 延迟不上报：`latency_frames_atomic` 恒 0，避免帧协商错位。
